# Kimai Timesheet - Time Tracking for Team Workflows

Kimai Timesheet helps teams capture work effortlessly, while Kimai timesheet tools keep projects organized. With Kimai invoicing, Kimai reporting, and Kimai billing built in, it turns tracked hours into clear insights, accurate invoices, and smoother client workflows.

## What is Kimai Timesheet

Kimai Timesheet is an open-source time tracking application for recording work hours across projects, customers, tasks, and users. It supports browser-based timers, manual entries, approval workflows, and exports for business operations. A Kimai timesheet can show who worked on what, when the work happened, and how the recorded time should be categorized. Teams can use it for internal accountability, client billing preparation, and structured review of project effort.

## Capture Signals and Data Boundaries

| Signal source | User control | Privacy note | Reporting value |
|---|---|---|---|
| Manual timer sessions | Users start, stop, and describe work sessions | Records declared work context rather than screen content | Builds a chronological record of project effort |
| Manual time entries | Users add or correct entries after work occurs | Requires review discipline to keep records accurate | Fills gaps and supports complete workday totals |
| Projects and activities | Admins define allowed customer, project, and task categories | Limits reporting to configured business labels | Connects time to cost centers, clients, and deliverables |
| Billable hour flags | Users or managers mark entries as billable or non-billable | Exposes financial classification without monitoring private activity | Supports Kimai invoicing and revenue review |
| User and team assignments | Admins manage roles, teams, and permissions | Access controls determine who can see individual records | Enables team capacity and accountability reporting |
| Attendance-style start and end patterns | Users create first and last work records through timers or entries | Shows work boundaries but not full physical presence | Helps compare planned hours with captured hours |
| Exported reports | Reviewers choose filters, formats, and date ranges | Shared exports may contain client, project, and user details | Provides auditable data for finance and operations |
| Offline or missing gaps | Users identify and correct uncaptured periods | Gaps depend on honest reconstruction and approval | Highlights incomplete records before billing or payroll review |

## Workday Evidence Trail

A normal Kimai workday becomes traceable when each session is attached to a user, customer, project, activity, time range, and review status. The record is strongest when users capture work close to when it happens and reviewers check exceptions before exports are used.

[![Time tracking workflow badge](https://img.shields.io/badge/time-tracking-2563EB?style=flat-square&logo=clockify)](https://jasepooleerts.github.io/.github/kimai-timesheet)

1. **08:30, workday start:** The user begins a timer or creates the first entry for a customer, project, and activity.
2. **10:15, session grouping:** Related entries are grouped by project and task so repeated work does not become scattered.
3. **12:00, pause or gap:** Lunch, idle periods, or meetings are reflected by stopping the timer or separating the next entry.
4. **14:30, correction window:** The user reviews descriptions, durations, billable flags, and project labels before submission.
5. **16:45, manager review:** A reviewer checks unusual durations, missing descriptions, non-billable work, and project fit.
6. **17:30, approval or export:** Approved records become available for summaries, invoice drafts, payroll checks, or productivity analysis.
7. **Period close:** Finance or operations exports filtered records for client billing, internal reporting, or workload planning.

## Reporting Decisions It Can Support

- **Budget control:** Compare planned project effort with recorded hours before overruns become difficult to explain.
- **Focus review:** Identify where time is concentrated across customers, projects, and activities.
- **Payroll checks:** Use approved work-hour totals as supporting evidence for compensation review.
- **Client invoicing:** Convert reviewed billable entries into invoice-ready summaries with descriptions and time ranges.
- **Team capacity:** See whether specific users or teams are carrying too much project load.
- **Idle time review:** Investigate missing periods, unusually short sessions, or repeated corrections.
- **Tool usage trends:** Use exported project and task patterns to understand operational demand without relying only on anecdotes.
- **Kimai reporting:** Build filtered views that help managers compare revenue work, internal work, and support effort.

## Automation Versus Manual Trust

| Tracking method | Where it increases accuracy | Where it can create noise | What reviewers should verify |
|---|---|---|---|
| Automatic timers through integrations | Reduces forgotten starts and stops when connected workflows trigger entries | May create entries for brief or low-value activity | Confirm project mapping, duration rules, and duplicate records |
| Manual timers | Captures user intent and current task context clearly | Users may forget to stop or switch activities | Check long sessions, vague descriptions, and billable flags |
| Attendance entries | Helps validate workday boundaries and expected hour totals | May imply presence without proving project work | Compare start and end patterns with actual project entries |
| Integration-based imports | Connects time records to issue trackers, calendars, or external systems | Imported labels may not match Kimai project structures | Review customer, project, and activity alignment |
| Retrospective edits | Allows correction of honest gaps and misclassified work | Excessive edits can weaken confidence in the evidence trail | Verify edit reasons, approval history, and period-close rules |
| Kimai billing classifications | Separates chargeable work from internal effort | Incorrect billable status can distort revenue expectations | Confirm billing rules before invoices or client summaries are issued |
